# Administrator authenticator recovery

For enrolled administrators, sign in with password, then use authenticator or one
saved provider recovery code. A recovery code is single-use. Verify fresh proof
and current password to replace codes or disable the authenticator; disabling
removes all admin assurance. Enroll/verify a replacement before privileged use.
All ordinary account/password/email/session tools remain available by own-account
identity; they never grant admin assurance.

If a provider action is uncertain, do not assume rollback. Sign in again, verify
the currently active authenticator or remaining recovery code, and inspect only
own account/session/security state. No raw key/code/session token belongs in a
support report, log, screenshot or URL. Keep backup codes offline privately.

Lost password plus every authenticator/recovery code has no automated bypass.
Real operation requires a named trusted owner, approved identity evidence and
review procedure, deliberate provider-supported credential recovery/revocation,
audit and new enrollment. This runbook does not authorize that production
operation or define its unresolved human evidence policy. Never edit provider
auth rows ad hoc or grant assurance directly. Current scope is local synthetic
software acceptance only; payments and hosted/launch gates remain closed.
