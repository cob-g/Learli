# Local matching availability preferences

Date: 2026-10-11. Authority: actual supervised `$build-feature Extend M3.6
rule-based matching with real availability preferences` request; **AUTHORIZED —
build-feature delegation**, not separate human blueprint approval.

The visitor supplies an IANA viewer time zone, explicit Any time or preferred
weekdays and one wall-clock band. The four bands partition the viewer day:
00:00–06:00, 06:00–12:00, 12:00–18:00, 18:00–24:00. These are consumed technical
search filters, not a customer lesson or availability promise. The entire
half-open elapsed candidate must fit the chosen weekdays/band, including DST.
Any time bypasses only preference filters; eligible actual-date candidates are
still required. No private learner/account information is read for matching.

The coordinator approved the pure preference and public candidate contracts in
`msg_02e392717ba2` and accepted the full-catalog bound in `msg_420459596c81`.
Matching considers all subject+level eligible tutors up to100 in at most five
20-slug batches. It filters the common effective window, orders earliest fitting
time then name/slug, and paginates five real matches. Above100 or on candidate
query overflow, the service reports temporary unavailability, never a partial
set described as global matches. The provider independently bounds rows/times.

Candidate policy is the existing explicit local simulation duration60,
step30, notice60, horizon14days and lifetime10minutes. Real operating policy
stays OPEN. Matching consumes the shared public candidate service under exact
parent-approved imports; expiry/time off/DST generation is not duplicated.

URL state contains only validated visitor filters. Unknown keys and unsafe
values are removed before page rendering to keep Next's serialized route state
safe too. Plain GET navigation remains functional without JavaScript; browser
zone detection is optional enhancement. No storage service, profile mutation,
consent policy, account timezone persistence, booking transition or external
integration is added.
